## 0.1 先建立全景：一次请求在推理引擎里的旅程

你敲下 `vllm serve` 后，用户的一条消息会经过：

```
用户消息
  → API Server          收请求（HTTP）
  → Tokenizer           文字切成 token id，比如 "你好" → [1234, 5678]
  → Scheduler           决定这一步把哪些请求的哪些 token 送进 GPU/NPU（continuous batching）
  → ModelRunner         准备张量、取 KV cache、调用 ↓
  → model.forward()     ★ 模型本体：本教程 9 课讲的就是这里面的代码
  → Sampler             从 logits 里选出下一个 token
  → Detokenizer         token id 变回文字，返回用户
```

**关键认知**：所谓"模型结构"，就是 `model.forward()` 里那棵 `nn.Module` 树——输入一叠 token id 和位置，输出一叠隐向量。引擎其他部分（调度、显存管理、通信）都是为它服务的。

**vllm-ascend 是什么**：vLLM 原生支持 NVIDIA GPU。vllm-ascend 是华为昇腾 NPU 的"硬件插件"——它通过 Platform 注册机制告诉 vLLM："NPU 上该用我的算子、我的注意力后端、我的模型实现"。GLM5-Next 的模型代码不在 vLLM 上游，就在这个插件里（第 9 课讲注册机制）。

## 0.2 手算一个迷你 Transformer（全程 4 维向量，可以拿草稿纸跟着算）

设一个玩具模型：词表 6 个词，隐层维度 hidden=4，1 层，注意力 1 个头。

这三个数是"尺寸参数"，先弄清它们各自管什么，后面手算才不会晕：

| 玩具参数 | 含义 | GLM5-Next 真实值 |
|---|---|---|
| 词表 6 | embedding 表有几行：token id 就是行号，查出来的是那一行 | 154880 |
| hidden=4 | **每个 token 用一个 4 维向量表示**，模型内部所有计算的向量宽度都是 4：embedding 查出的行是 4 维、RMSNorm 按 4 个维度归一化、Q/K/V 都是 4 维的投影 | 4096 |
| 1 层 | "层" = Step 5 那套"注意力子层 + FFN 子层"骨架。堆叠几遍就是几层，1 层 = 这条流水线只走一遍 | 45 层 |
| 1 个头 | 注意力头数：hidden=4 不拆分，整个 4 维当一个头算注意力（Step 3 手算里的 √d=√4=2） | 64 头 × 每头 256 维 |

一句话：**hidden=4 是"向量的宽度"，1 层是"流水线重复几遍"**——都只是为了能拿草稿纸手算；把宽度换成 4096、层数换成 45，就是真模型。

### Step 1：Embedding——查表

embedding 是"离散符号 → 连续向量"的翻译器：模型只会算矩阵和向量，而 token id 只是个整数、没有含义可言。embedding 表是一张 `词表数 × hidden` 的大查表，每个 token id 对应词表里一行向量。id=2 就取 embedding 矩阵的第 2 行：

```
token id 2 → [0.1, -0.2, 0.5, 0.3]
```

之后模型世界里的所有计算都发生在这 4 维向量上。

关键在于**这些向量是训练学出来的**——语义相近的词（"猫"和"狗"）向量方向接近，"含义"就变成了可计算的几何关系。有了向量，后面的一切才能运转：RMSNorm 归一化它、Q/K/V 投影它做注意力、FFN 加工它。

出口处还有个反向操作（Step 7 的 LM head）：拿最后一个 token 的隐向量去和全表比内积，得到"下一个词是每个 id 的分数"——所以 embedding 表一头管"读入"，一头管"预测"。

### Step 2：RMSNorm——只做缩放的归一化

对 x = [1, 2, 3, 4]（手算）：

```
mean(x²) = (1+4+9+16)/4 = 7.5
rms = √(7.5 + ε) ≈ 2.739          # ε=1e-5 防除零，可忽略
x_norm = x / 2.739 = [0.365, 0.730, 1.095, 1.460]
输出 = x_norm ⊙ γ                  # γ 是可学习的缩放权重（逐维）
```

对比 LayerNorm（一句话即可）：LayerNorm 先减均值再除标准差；RMSNorm 不减均值，只除均方根——少一步、更快，效果几乎一样，所以现代模型几乎都用它。

### Step 3：注意力——三种角色 Q/K/V

每个 token 的向量被三个矩阵投影成三种角色：

- **Q（Query，查询）**：我在找什么信息
- **K（Key，键）**：我能提供什么标签
- **V（Value，值）**：我实际携带的内容

注意力 = 拿自己的 Q 去和所有 token 的 K 做匹配打分，按分数加权取大家的 V。

手算（2 个 token，√d=√4=2）：

```
token A: q=[1,0,1,0]  k=[1,0,0,0]  v=[1,0,1,0]
token B: q=[2,1,0,0]  k=[0,1,0,0]  v=[0,1,0,1]

A 看两个 K 的得分：q_A·k_A = 1，q_A·k_B = 0
  → 除以 √d → [0.5, 0] → softmax → [0.622, 0.378]
  → 输出 = 0.622·v_A + 0.378·v_B = [0.622, 0.378, 0.622, 0.378]

B 看两个 K 的得分：q_B·k_A = 2，q_B·k_B = 1
  → 除以 √d → [1.0, 0.5] → softmax → [0.622, 0.378]
  → 输出 = 0.622·v_A + 0.378·v_B
```

softmax（手算）：`softmax([1.0, 0.5]) = [e¹, e⁰·⁵]/(e¹+e⁰·⁵) = [2.718, 1.649]/4.367 ≈ [0.622, 0.378]`。

**因果掩码**：生成场景里 token B 不许看"未来"，只看自己和之前的。实现上就是把非法位置的分数设成 -∞ 再 softmax（softmax 后变 0）。第 4 课的 `cu_seqlen_ks/ke` 干的就是标记每行合法区间。

### Step 4：多头——并行看多种模式

hidden=4 拆成 2 个头、每头 2 维，各算一遍 Step 3 再拼回 4 维。手算（沿用 Step 3 的 q/k/v，切开各自算）：

```
token A: q=[1,0 | 1,0]  k=[1,0 | 0,0]  v=[1,0 | 1,0]
token B: q=[2,1 | 0,0]  k=[0,1 | 0,0]  v=[0,1 | 0,1]
              头1        头2

── 头 1（√d=√2，只看前 2 维，和别的头互不干扰）──
A 打分: q_A·k_A = 1,  q_A·k_B = 0
  → ÷√2 → [0.707, 0] → softmax → [0.670, 0.330]
  → 输出A(头1) = 0.670·[1,0] + 0.330·[0,1] = [0.670, 0.330]
B 打分: q_B·k_A = 2,  q_B·k_B = 1
  → ÷√2 → [1.414, 0.707] → softmax → [0.670, 0.330]
  → 输出B(头1) = [0.670, 0.330]

── 头 2（√d=√2，只看后 2 维）──
A 打分: q_A·k_A = 0,  q_A·k_B = 0 → softmax → [0.5, 0.5]
  → 输出A(头2) = 0.5·[1,0] + 0.5·[0,1] = [0.5, 0.5]
B 同理 → 输出B(头2) = [0.5, 0.5]

── 拼回 4 维 ──
输出A = [头1输出 | 头2输出] = [0.670, 0.330, 0.5, 0.5]
输出B = [0.670, 0.330, 0.5, 0.5]
```

三个观察：

1. **每个头独立做一遍完整的 Step 3**（打分 → softmax → 加权 V），只是维度从 4 缩到 2，互不通信
2. **两个头行为不同**：头 1 区分了 token A/B（权重 0.670/0.330），头 2 的 K 全是零向量 → 均匀注意力 0.5/0.5，等于这个头"没找到可关注的模式"——这就是"多头看多种模式"的直观体现：真模型里有的头盯语法、有的头盯指代
3. 数字和 Step 3 单头不同是正常的：每头维度变了（√d 从 2 变 √2），打分自然变。最后通常还会过一个大矩阵 W_o 把拼回的 4 维再混合一次

为什么多头：不同的头可以关注不同模式（一个头盯语法、一个头盯指代）。GLM5-Next 的 MLA 层是 64 个头、每头 256 维，64 个这样的"小注意力"并行算完再拼接（MLA 里还多了低秩压缩，第 3 课讲）。

### Step 5：残差连接 + pre-norm——每层的骨架

一个标准 Transformer 层长这样（叫 **pre-norm**）：

```
x = x + Attention(Norm(x))      # 注意力子层
x = x + FFN(Norm(x))            # FFN 子层
```

残差（`x = x + ...`）像高速公路主路，每个子层只是从主路下去加工一下再回来——梯度可以沿主路直达浅层，网络深了也能训练。**第 2 课你会看到，MHC 把这条"单车道主路"升级成"4 车道"**。

### Step 6：FFN / SwiGLU——逐 token 的两层 MLP

```
FFN(x) = down( silu(gate(x)) ⊙ up(x) )
```

`gate` 和 `up` 都是 4096→12288 的升维矩阵（代码里合并叫 `gate_up_proj`），`down` 是 12288→4096 的降维。silu(x) = x·sigmoid(x)，手算：silu(1) = 1×0.731 = 0.731（正的略缩放放行）、silu(-1) ≈ -0.269（负的压向 0）。⊙ 是逐元素乘。

**为啥先升维再降维**（升到 12288 再压回 4096）：

1. **宽空间里有更多"并行检测器"**。gate 这一步相当于把 token 投影成 12288 个"特征打分"（这个 token 是不是代码？是不是疑问句？……）。升维 = 一次能同时检测更多模式，这是模型表达能力的来源——如果一直在 4096 维里打转，几层矩阵连乘理论上可以合并成一层，叠再深也学不出复杂函数
2. **silu + ⊙ 是"筛选"**：silu 把负分压向 0（"这个特征与本 token 无关，关掉"），正分放行；再和 `up` 的输出逐元素相乘，相当于门控——12288 维里只有一部分"通道"被打开。**先展开才能筛，没有展开就没有可筛的东西**
3. **降维是被迫的**：残差连接 `x = x + FFN(...)` 要求加法两边形状一样，所以必须压回 4096

`gate_up_proj` 为啥"合并叫一个"：gate 和 up 是两个独立矩阵，但运行时永远一起用，干脆存成一个 4096→2×12288 的权重，算的时候一次矩阵乘、再劈成两半——GEMM 更大更高效（第 6 课 MoE 里会到处见到这种合并写法）。

FFN 起什么作用：如果说注意力是"token 之间开会交换信息"，FFN 就是"每个 token 回工位独立消化"——它对**每个位置单独**做一次非线性变换，token 之间互不通信。具体有三点：

1. **非线性加工**：注意力本质是加权平均（线性操作），没有 FFN 的非线性，叠 100 层也等价于一层。先升维到 12288 在"更宽的空间"里做计算，再降回 4096——先展开、再筛选、再压缩
2. **知识的主要存放地**：Transformer 的大部分参数和"世界知识"都存在 FFN 的权重矩阵里（可以把 FFN 看成键值记忆库：第一层矩阵当 key 检测"当前是什么模式"，第二层矩阵当 value 往隐向量里写入对应信息）
3. **参数大头**：GLM5-Next 里 FFN（MoE 的 288 个专家）才是参数主力——所以第 6 课的 MoE 讲的就是"FFN 太大怎么办"：288 个小 FFN 当专家，每个 token 只激活 8 个 + 1 个共享，"大而不贵"

一句话：**注意力决定"看谁"，FFN 决定"看完之后怎么想"**。

### Step 7：LM head——从隐向量到下一个 token

最后一个 token 的隐向量 × embedding 矩阵的转置 → 6 个分数（logits）→ softmax → 概率 → 选一个（贪心取最大，或按概率采样）。

**隐向量是啥**：模型跑完整个流水线后，每个 token 位置上留下的加工完的向量（玩具里 4 维，真模型 4096 维）——它对 token 查 embedding 后逐层过"注意力 + FFN"被反复加工，是模型对"这个 token 在上下文里是什么意思"的最终理解，是算出来的中间结果，不是权重。

为啥只取**最后一个**位置的？因果掩码保证了最后的 token "看过"它前面的所有人——它的隐向量已浓缩了整句话的信息。所以预测"下一个词"只需要它：

```
"我爱吃苹" 共 4 个 token → 出口有 4 个隐向量
预测下一个词只用第 4 个（"苹"）的隐向量
  → 4 维向量 × embeddingᵀ（4×6）→ 6 个分数
  → softmax → 概率 → "果" 的分数最高 → 选中
```

补充：prefill 时前面位置的隐向量**不是白算的**——它们的意义在于层层交换信息，把内容"汇"到最后一个位置；第 8 课的 MTP 投机解码，用的正是这个"最后位置隐向量"来猜出不止一个下一个 token。

后面 9 课的所有"高大上"模块，都是这 7 步的**变体 + 工程化**：

## 0.3 KV cache：为什么 AI infra 的人满嘴都是它

### 问题

生成是自回归的：生成第 100 个 token 需要前 99 个 token 都参与注意力。如果没有缓存，每生成一个 token 就要把前 99 个的 K、V 全部重算一遍——总计算量 O(n²)。

### 方案

每个 token 算过一次后，把它的 **K 和 V 存下来**（Q 不用存，Q 每步都是新的）。下一步只需算新 token 的 QKV，历史部分直接查表。这就是 KV cache。

两个术语（代码里到处出现）：
- **prefill**：用户发来一段 1000 token 的 prompt，一次性并行算完这 1000 个 token 的 KV 并存好
- **decode**：之后每次只算 1 个新 token，逐个往外蹦

### 显存公式（必须会算）

```
KV cache 显存 = 2(K和V) × 层数 × KV头数 × 每头维度 × 序列长度 × 每数字节数
```

例：一个普通 45 层模型，64 头 × 每头 256 维（K、V 各 256），1M token 上下文，BF16（2 字节）：

```
2 × 45 × 64 × 256 × 1,000,000 × 2B = 2.9 TB   ← 任何单机都放不下
```

**为什么这个公式是本教程的主线**：GLM5-Next 的两大结构创新，本质都是在动这个公式——
- **MLA（第 3 课）**：把"每头独立的 K/V"压缩成一个共享隐向量 → 公式里的 `64×256×2` 变成 `512`，缩 ~64 倍
- **KDA（第 5 课）**：部分层干脆不要 KV cache，用固定大小的"状态矩阵"记住历史 → 公式里 `× 序列长度` 变成 `× 1`
- **DSA/KPool（第 4 课）**：cache 可以省着算——每步只对 top-k 个历史 token 做注意力

## 0.4 RoPE：位置信息怎么进注意力（30 分理解即可）

注意力的打分是内积，**天生不知道 token 的先后顺序**——把输入顺序打乱，输出只是跟着乱序，模型无法区分"猫追狗"和"狗追猫"。

RoPE（旋转位置编码）的方案：把每个 token 的 Q、K 向量按"位置 × 固定角度"旋转，这样 Q_i·K_j 的内积只取决于**相对距离 i-j**。三条结论够用：

1. RoPE 只加在 Q/K 上，**不加在 V** 上（V 是内容，不需要方向感）
2. 旋转角度与位置成正比
3. RoPE 有"长文本外推"的改良家族（ YaRN 等词第 3 课会出现）

> 记住一个反常点：GLM5-Next 的 MLA 层**完全不用 RoPE**（config 里 `qk_rope_head_dim=0`），这是第 3 课要专门讨论的设计。

## 0.5 MoE：不是所有人都需要干所有活

Dense FFN（Step 6）：每个 token 都要过完整的 12288 维 FFN。
MoE（Mixture of Experts）：备好 N 个小 FFN（专家），每个 token 由一个"路由器"挑出 top-k 个专家来干活。

手算（4 个专家选 2 个，sigmoid 打分）：

```
路由器输出 logits = [2.0, 0.5, 1.5, 0.1]
sigmoid → 分数   = [0.881, 0.622, 0.818, 0.525]
top-2 → 专家 0 和专家 2 入选
权重归一化：0.881/(0.881+0.818)=0.518，0.818/(...) = 0.482
输出 = 0.518·专家0(x) + 0.482·专家2(x)
```

两个术语：
- **shared expert（共享专家）**：不管路由结果如何，每个 token 都必过的 1 个专家（保证"常识"不丢失）
- **路由精度**：路由是"选谁"的硬决策，分数抖一点选择就变，所以路由打分用 FP32（第 6 课的 `force_fp32_compute=True`）

参数经济学：GLM5-Next 每层 288 个专家，每 token 只激活 8 个 + 1 共享。总参数巨大、单 token 计算量小——"大而不贵"。

## 0.6 TP / EP / PP：权重是怎么被切到多张卡上的

单卡放不下 300B 参数，所以要并行切分。读代码时认得这三个词即可：

| 缩写 | 全称 | 切什么 | 代码特征 |
|---|---|---|---|
| **TP** | Tensor Parallel | 单个权重矩阵 | `ColumnParallelLinear`（切输出列，入口不用通信）/ `RowParallelLinear`（切输入行，**出口要 all-reduce**） |
| **EP** | Expert Parallel | MoE 的专家 | `get_ep_group()`，288 个专家分给 8 张卡，每卡 36 个 |
| **PP** | Pipeline Parallel | 按层分段 | `PPMissingLayer`（不归我这段的层用占位符）、`IntermediateTensors`（段间交接的行李箱） |

一句提神的话：**TP 切矩阵时通信发生在前后向；EP 切专家时通信是"把 token 邮寄给专家所在的卡"**。

另外两个高频词：
- **continuous batching**：调度器在 token 粒度攒批，不等整条请求结束，吞吐的关键
- **ACLGraph / torch.compile**：把 Python 动态执行图"固化"成设备上的静态图反复回放（省 CPU 调度开销）。代价是形状必须固定——所以代码里会有预分配 buffer、固定形状哨兵这些"怪写法"，第 2/4 课都会遇到

## 0.7 读引擎向代码时的速查表

后面课文会撞到这些词，先混个脸熟：

| 词 | 一句话解释 |
|---|---|
| FFN | Feed-Forward Network（前馈网络）：信息只单向流动（无循环/反馈）的网络；Transformer 里指 Step 6 那个两层 MLP，FFN/MLP/feed-forward 层基本同义 |
| LM head | Language Model head："head" 指接在主干顶端的输出层（换 head 换任务）；LM head 专门做"预测下一个词"——隐向量 × embeddingᵀ → 词表分数（Step 7） |
| attention backend | 每种注意力（MLA/GDN/…）配套的"算子实现 + 元数据管理"包 |
| KVCacheSpec | 模型向引擎申报"我这层的 cache 长什么形状" |
| block_table / 分页 | KV cache 像 OS 内存一样按"页"分配；block_table 是逻辑页→物理页的页表 |
| slot_mapping | 本步每个新 token 应该写到 cache 的哪个物理格 |
| attn_metadata / forward_context | 引擎传给每层的"本步批次的元信息"（序列长度、位置、页表…） |
| `torch.ops._C_ascend.*` | 昇腾自定义 C++ 算子；`torch.ops.vllm.*` 是 vLLM 注册的融合算子 |
| prefix | 模块在整棵树里的名字路径（如 `model.layers.12.self_attn`），权重加载全靠它对号 |

## 0.8 读模型代码的方法论（比知识点更重要）

1. **`named_parameters()` 是地图**。对任何模型打印它，就得到全部权重名+形状：
   ```python
   for name, p in model.named_parameters():
       print(name, tuple(p.shape))
   ```
   拿这份清单对照 checkpoint 的权重名，是读懂任何新模型的第一步（第 9 课整课都在讲这件事）。
2. **形状标注法**。读每个 forward 都在草稿上标张量形状：`[T, 4096]`（T=本步 token 数）。形状对得上，逻辑基本就对；形状对不上，一定理解错了。
3. **先 `__init__` 后 `forward`**。init 决定"这层拥有什么部件"，forward 决定"部件怎么串"。先读完 init 的部件清单，forward 就只是流水线。
4. **单测是活的文档**。`tests/ut/models/test_glm5_next_*.py` 里有写死的输入输出，跑一遍比读十遍注释快。
5. **认亲法**。GLM5-Next 大量模块是 DeepSeek V4 / Kimi GDN 的 NPU 适配版，看到陌生类名先想"它的上游亲戚是谁"。
