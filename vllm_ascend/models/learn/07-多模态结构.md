## 0. 新手包：ViT 从零——模型怎么"看"图

语言模型吃的是 token 序列，图片不是序列，所以要先"翻译"：

```
一张 448×448 的图
  → 按 14×14 剪成小格（像把照片剪成邮票）：32×32 = 1024 格
  → 每格经一个小卷积压成一个 1024 维向量（patch embedding）
  → 一张图 = 1024 个"视觉 token" 的序列 ← Transformer 就能吃了！
  → 2×2 相邻格合并（merge）：1024 → 256 个 token（省 4 倍计算）
  → 每个向量升到 4096 维，冒充"文字 token"注入语言模型
```

三个必然的问题与答案：
- **顺序/位置怎么表达**？格子的行列位置用 2D RoPE（文本是 1D 位置，图是行列两个方向）
- **多张图一批算怎么办**？每张图长度不同 → 用 `cu_seqlens` 标记每张图的起止，把所有图首尾相接成一条长序列（varlen，课文 §2）
- **视频呢**？时间也是一维：连续帧的格子组成 3D patch（课文中 `temporal_patch_size=2`：每 2 帧一组）

本课的视觉塔就是这套流程 + 工程细节，看懂上面这张图再读课文就毫无悬念。

## 1. 顶层装配（[:643-693](../glm5_next_multimodal.py#L643-L693)）

```python
@MULTIMODAL_REGISTRY.register_processor(
    Glm4vMultiModalProcessor,                      # 预处理器复用 GLM4V 的
    info=AscendGlm5NextProcessingInfo,             # 只覆写 token 估算
    dummy_inputs=AscendGlm5NextDummyInputsBuilder) # 原样继承
class AscendGlm5NextForConditionalGeneration(Glm4vForConditionalGeneration,

        super(Glm4vForConditionalGeneration, self).__init__()   # 跳级初始化
        with self._mark_tower_model(vllm_config, {"image", "video"}):
            self.visual = AscendGlm5NextVisionTransformer(...)
        with self._mark_language_model(vllm_config):
            self.language_model = init_vllm_registered_model(
                hf_config=config.text_config,
                architectures=["Glm5NextForCausalLM"])       # ← 文本模型复用！
```

三个细节：
- `super(Glm4vForConditionalGeneration, self).__init__()` **显式跳级**：绕过直接父类的 init，自己控制装配顺序。
- `_mark_tower_model / _mark_language_model` 是 vLLM 多模态的上下文标记：告诉引擎哪些子模块是视觉编码器（不参与 KV cache、可用 data-parallel TP 模式）。
- `init_vllm_registered_model(architectures=["Glm5NextForCausalLM"])` 按注册名拉起第 2 课的文本模型——第 9 课的注册表在这里兑现价值。

HasInnerState/IsHybrid 的三个 mamba 接口（[:650-662](../glm5_next_multimodal.py#L650-L662)）直接**转发给文本模型类**的类方法——多模态壳自己不懂 KDA 状态，纯委托。

## 2. 视觉塔解剖（[:250-330](../glm5_next_multimodal.py#L250-L330)）

参数（vision_config）：depth=24, hidden=1024, heads=16（head_dim 64）, patch=14, image=448, out=4096, spatial_merge=2, swiglu_limit=10。

```
图片 (3, T帧, 448, 448)
   │ AscendGlm5NextVisionPatchEmbed（继承 GlmOcr：Conv3d，kernel=patch×patch×temporal 2）
   ▼
patch tokens [T', (448/14)²=1024, 1024]
   │ + 2D RoPE（partial_rotary_factor=0.5，is_neox，max 8192）+ QK 各自 RMSNorm
   ▼
24 × AscendGlm5NextVisionBlock（:144）
      x = x + attn(norm1(x), cu_seqlens, cos, sin)     # varlen 打包注意力
      x = x + mlp(norm2(x))                             # SwiGLU + clamp(10)
   ▼
post_layernorm（RMSNorm 1024）
   │
   ├─ downsample：Conv2d(1024→4096, kernel=2, stride=2)   # 2×2 patch 合 1
   └─ merger（:199）：proj(4096) → LayerNorm → GELU → gate_up(10240) → SwiGLU(clamp) → down(4096)
   ▼
视觉 embedding [T', 256 合并后, 4096]  →  作为 inputs_embeds 注入语言模型
```

要点：

1. **Block.forward 签名**（[:176](../glm5_next_multimodal.py#L176)）：`cu_seqlens` 是 varlen 打包的关键——多张不同尺寸图的 patch 序列拼成一个 batch，靠 cu_seqlens 分段，不做无效 padding。
2. **PatchMerger 的 context_dim 用 `projection_intermediate_size=10240`**（[:309](../glm5_next_multimodal.py#L309)），而非文本 config 的 intermediate_size——这是 GLM5-Next vision config 独有字段（config 里 [:320-323](../../transformers_utils/configs/glm5_next.py#L320-L323) 注释专门解释）。
3. **downsample（Conv2d 1024→4096）与 merger 并存**：downsample 输出与 merger 输出在 GLM-OCR 上游的融合逻辑里组合（塔继承自 GlmOcrVisionTransformer，前向在上游）。
4. 视觉塔**不量化**（`quant_config=None`，[:683](../glm5_next_multimodal.py#L683)）。

## 3. 为什么 VisionRMSNorm 要单独手写（[:63](../glm5_next_multimodal.py#L63)）

```python
class Glm5NextVisionRMSNorm(nn.Module):
    """Keep this vision-specific implementation independent from vLLM's RMSNorm.
    On Ascend, the latter can acquire a quantization bias from the global text
    quantization config even though the vision tower itself is unquantized."""
```

文档字符串就是答案：vLLM 的通用 RMSNorm 会被**全局量化配置**注入 bias，而视觉塔必须保持无量化纯净。**"该共享时共享，该隔离时隔离"**——判断依据不是代码相似度，而是配置污染路径。

`Glm5NextSiluAndMul`（[:49](../glm5_next_multimodal.py#L49)）同理：clamp 语义与 `SiluAndMulWithClamp` 相同但 gate 和 up 分开 clamp（gate 只 clamp 上界，up 双向 clamp）——和文本侧的激活细节不同，所以不复用。

## 4. 权重加载（[:340-389](../glm5_next_multimodal.py#L340-L389)）

视觉塔**手写** load_weights 而不用 AutoWeightsLoader，因为要做两件严格检查：
- checkpoint 同名权重重复出现 → raise（[:346](../glm5_next_multimodal.py#L346)）
- 同一目标参数被加载两次 → raise（[:360](../glm5_next_multimodal.py#L360)）
另外把异常重抛时**带上 checkpoint 形状 vs 目标形状**（[:377-383](../glm5_next_multimodal.py#L377-L383)）——调试体验优先的写法。[`:386-388`](../glm5_next_multimodal.py#L386-L388) 注释解释了为什么完整性检查按"累计加载结果"而非"本次调用"。

## 5. ProcessingInfo：token 数预算（[:392-631](../glm5_next_multimodal.py#L392-L631)，选读）

引擎需要提前知道"一张图/一段视频最多占多少 token"来分配资源：

- `get_supported_mm_limits`: image 无限，video 最多 1 个（[:393](../glm5_next_multimodal.py#L393)）
- `get_num_image_tokens` = patch 数 / merge²（[:489](../glm5_next_multimodal.py#L489)）
- 视频 token = 视觉 token + 每帧时间戳 token（上限 300 个时间戳，[:543](../glm5_next_multimodal.py#L543)）+ 边界 token
- `_is_glmga_model`（[:396](../glm5_next_multimodal.py#L396)）：GLM5Next 视频用固定 fps 时间戳构造（GLMGA 风格），不是 GLM4.6V 的按时长采样——一行 isinstance 判断换一条采样策略

> 时间不够就跳过本节细节，记住结论：这类类只做"算数"，不碰张量。

## 6. 数据流全程（终考素材）

```
图片 → processor(展开 image_token_id 为 N 个占位) → 视觉塔 embedding
  → 输入序列: [文本 tokens..., img_start, N×视觉embedding, img_end, 文本...]
  → 语言模型（Glm5NextForCausalLM，即第 1-6 课的一切）
```

`is_vl_first_layer`（第 2 课 [:2076](../glm5_next.py#L2076)）因此成立：多模态第 0 层收到的 `inputs_embeds` 是完整长度，与 FlashComm1 的分片输出不匹配，需要特判。
