## 0. 新手起步：config 到底是个啥

把大模型想象成一栋按图纸施工的大楼：

- **checkpoint（权重文件）** = 砖头水泥，是训练好的参数本身
- **config（配置）** = 施工图：多少层、每层多宽、用哪种注意力——全是数字和开关
- **模型代码** = 施工队：读图纸，把砖头砌成楼

`config.json` 是随权重一起发布的 JSON 文件。本课的三个 Python 类就是它的"解析器"：把 JSON 字段变成代码能查询的属性。**先学 config 的原因**：45 层里每层长什么样，完全由 `layer_types`/`mlp_layer_types` 这两个字段决定——不理解图纸，砌墙就是盲人摸象。

## 1. 三层配置结构

HuggingFace 多模态模型的标准做法——顶层配置套子配置：

```
Glm5NextConfig (model_type="glm5_next")          ← 顶层，多模态入口
├── text_config   → Glm5NextTextConfig  (model_type="glm5_next_text")   ← 文本主干
└── vision_config → Glm5NextVisionConfig(model_type="glm5_next_vision") ← 视觉塔
```

顶层还持有 6 个多模态 token id：

| 字段 | 默认值 | 用途 |
|---|---|---|
| `image_token_id` | 154854 | 图像占位 token（预处理时展开成 N 个） |
| `video_token_id` | 154855 | 视频占位 token |
| `image_start/end_token_id` | 154830/154831 | 图像边界标记 |
| `video_start/end_token_id` | 154832/154833 | 视频边界标记 |

**兼容性设计**（[`glm5_next.py:365-370`](../../transformers_utils/configs/glm5_next.py#L365-L370)）：如果 checkpoint 是纯文本模型（没有嵌套 `text_config`），顶层会把 kwargs 直接摊平传给 `Glm5NextTextConfig`，这样一个配置类同时服务文本/多模态两种权重格式。

## 2. TextConfig 主干参数：先记住这组数字

```python
vocab_size=154880        # 词表 ~15.5 万
hidden_size=4096         # 隐层维度
num_hidden_layers=45     # 45 层 decoder
num_attention_heads=64   # 64 个头 → head_dim = 4096/64 = 64
max_position_embeddings=1013760  # 100 万上下文！
rms_norm_eps=1e-5
```

## 3. 灵魂设计：逐层异构布局

GLM5-Next 最特别的地方——**45 层不是每层都长一样**，由两个列表逐层描述：

### 3.1 `layer_types`：注意力类型

```python
layer_types: list[str]  # 每层取值："linear_attention" | "deepseek_sparse_attention"
```

- `"deepseek_sparse_attention"`（DSA 层）：走 MLA + Lightning Indexer 稀疏注意力，有 KV cache
- `"linear_attention"`（KDA 层）：走 Kimi Gated DeltaNet 线性注意力，只有 O(1) 的循环状态

推理引擎据此判断该层是否分配 KV cache block（`layers_block_type` 属性把这两类映射成 vLLM hybrid 引擎认识的 `"attention"` / `"linear_attention"` 两种 block，[`configs/glm5_next.py:272-283`](../../transformers_utils/configs/glm5_next.py#L272-L283)）。

### 3.2 `mlp_layer_types`：FFN 类型

```python
mlp_layer_types: list[str]  # 每层取值："dense" | "sparse"
```

老式写法 `first_k_dense_replace=k`（前 k 层 dense，其余 sparse）会被自动转换成新列表格式（[`configs/glm5_next.py:172-180`](../../transformers_utils/configs/glm5_next.py#L172-L180)）。

> **默认配置下 `first_k_dense_replace=0`**：即 45 层全部是 MoE！第 0 层连 dense FFN 都没有，这比 DeepSeek V3（前 3 层 dense）更激进。

### 3.3 在模型侧如何消费

`AscendGlm5NextDecoderLayer.__init__`（[`glm5_next.py:2080-2127`](../glm5_next.py#L2080-L2127)）做两次分叉：

```python
if _is_kda_layer(config, layer_idx):      # 查 layer_types[layer_idx]
    self.self_attn = KimiGatedDeltaNetAttention(...)
else:
    self.self_attn = AscendGlm5NextMLAAttention(...)   # MLA + DSA

if self.is_moe and mlp_type == "sparse":  # 查 mlp_layer_types[layer_idx]
    self.mlp = AscendGlm5NextMoE(...)
else:
    self.mlp = AscendGlm5NextMLP(...)
```

## 4. MLA 参数组

```python
mla=True
q_lora_rank=1536          # Q 的 LoRA 低秩压缩维度
kv_lora_rank=512          # KV 联合压缩维度（MLA 的核心省显存手段）
qk_nope_head_dim=256      # 每个 head 的 nope 部分
qk_rope_head_dim=0        # ← 注意：0！传统 MLA 有 64 维 RoPE，这里没有
v_head_dim=256
mla_nope=True             # skip_rope=True，完全不做 RoPE
```

**疑问点先挂起**：`qk_rope_head_dim=0` + `mla_nope=True` 意味着这个 MLA 变体完全没有旋转位置编码。位置信息去哪了？第 03/04 课读注意力代码时揭晓。

## 5. DSA Indexer 参数组

```python
index_head_dim / index_topk / index_n_heads  # Indexer 的 QK 头维度、每 token 选多少个 top-k key
index_kpool=16                    # ★ Ascend 特有：KPool 压缩池大小
index_kpool_compress=True         # 状态压缩开关
index_kpool_always_select_tail=True
index_dsa_use_layernorm=True
```

`index_kpool` 是这个插件相对上游 DSA 的**独有创新**：把被淘汰出 top-k 的 key 压缩进一个小池子（pool），既保精度又控制显存——具体机制第 04 课展开。

## 6. KDA 线性注意力参数组

```python
linear_head_dim=128       # KDA 每头维度
linear_num_heads=64
linear_conv_kernel_dim=4  # 短卷积核（intra-chunk 混合）
linear_lower_bound=-5.0   # 门控下界（gate 数值稳定性）
```

checkpoint 可能用嵌套 `linear_attn_config` 字典存这些字段，构造时会摊平（[`configs/glm5_next.py:85-100`](../../transformers_utils/configs/glm5_next.py#L85-L100)），再通过 `linear_attn_config` property 合成 dict 喂给上游 `KimiGatedDeltaNetAttention`（[`:222-242`](../../transformers_utils/configs/glm5_next.py#L222-L242)）——一进一出的适配层。

## 7. MHC 超连接参数组

```python
mhc=True
mhc_num_residual_streams=4   # hc_mult：残差流数量
mhc_sinkhorn_iterations=20   # Sinkhorn 归一化迭代次数
mhc_tau=0.05
mhc_post_mult_value=2.0
```

传统 Transformer 只有 1 条残差流：`x = x + attn(x)`。MHC 把隐状态扩成 **4 条并行流**，每层用可学习矩阵混合。这就是为什么 `DecoderLayer` 里有 `hc_attn_fn/hc_attn_base/hc_attn_scale` 等 6 个额外参数。

## 8. MoE 参数组

```python
n_routed_experts=288       # 288 个路由专家
num_experts_per_token=7    # 代码默认 7，但 checkpoint 里 num_experts_per_tok=8
n_shared_experts=1         # 1 个共享专家（每 token 必走）
scoring_func="sigmoid"     # sigmoid 路由（非 softmax）
routed_scaling_factor=2.5
moe_intermediate_size=2048 # 专家 FFN 中间维度
use_grouped_topk=True
```

**一个经典坑**（[`configs/glm5_next.py:107-118`](../../transformers_utils/configs/glm5_next.py#L107-L118) 注释讲得很清楚）：checkpoint 用 sglang 风格字段名 `num_experts_per_tok`，如果只读自己代码的默认值 7，路由专家数就错了。所以这里用 `kwargs.get()` 做**双名并存**兼容。

## 9. 三个值得抄进笔记的工程细节

### 9.1 `layer_types` 延迟赋值绕过 transformers 校验

```python
# configs/glm5_next.py:167-171 的注释
# transformers 的 @strict PretrainedConfig 会在 super().__init__() 末尾
# 用 ALLOWED_LAYER_TYPES 校验 layer_types，而 GLM5-Next 自定义的
# "deepseek_sparse_attention" 不在白名单里 → 先 super() 再赋值
```

[`configs/glm5_next.py:209-220`](../../transformers_utils/configs/glm5_next.py#L209-L220)：`super().__init__()` 之后才 `self.layer_types = layer_types`。**读第三方库源码时，赋值顺序本身就是信息。**

### 9.2 `__setattr__` / `__getattribute__` 镜像机制

`Glm5NextConfig` 重载了这两个魔法方法（[`:398-424`](../../transformers_utils/configs/glm5_next.py#L398-L424)）：任何对顶层配置的属性读写都会**自动转发到 text_config**（除了 `_UNMIRRORED_KEYS` 白名单）。这样上层 vLLM 代码拿 `hf_config.num_hidden_layers` 时不用关心文本参数嵌套在子配置里。

代价：每次属性访问都多一层 `__getattribute__` 开销，且白名单必须精心维护（`architectures`、`torch_dtype` 若被镜像会变 None，导致模型类解析失败）。

### 9.3 `is_mla` / `is_moe` / `is_kda_layer` 这组 property

这是 vLLM 引擎和模型代码之间的**查询接口**：引擎问"你是 MLA 吗？这层是 KDA 吗？"，配置回答。第 05 课会看到 `layers_block_type` 直接决定 KV cache manager 的行为。

## 10. 本课小结：一图流

```
45 层 Decoder，每层 = [MHC 混合] → [注意力: KDA | MLA+DSA] → [MHC 混合] → [FFN: MoE(288选8) | dense]
              ↑                                                        ↑
        4 条残差流                                             共享专家×1 + 路由专家×8
              ↑
     第 0 层入口 expand，最后一层 mean 合并

KV 策略: DSA 层 → MLA 压缩 KV + Indexer top-k + KPool
状态策略: KDA 层 → O(1) 循环状态（mamba 式管理）
长上下文: 1M tokens
```
